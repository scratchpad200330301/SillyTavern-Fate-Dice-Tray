# 命运骰台 0.3.0 · 自动掷骰试用版

这是 SillyTavern 原生 UI 扩展程序，不是酒馆助手脚本，也不是服务器插件。依据官方文档及本机 SillyTavern 1.18.0 release 的接口制作。无需酒馆助手、Extras、额外模型或网络服务。

随机判定在浏览器本地完成，结果通过官方生成前拦截器附加到当轮请求。扩展不需要额外模型接口，不修改酒馆核心文件。

## 安装

推荐使用酒馆自带的 URL 安装：

1. 打开“扩展 → 安装扩展”。
2. 粘贴仓库地址：https://github.com/scratchpad200330301/SillyTavern-Fate-Dice-Tray
3. 确认安装，按酒馆提示刷新页面。默认分支为 main，不需要填写其他文件地址。
4. 点击输入栏正上方的“命运骰台”按钮打开窗口；也保留扩展菜单和设置入口。自动掷骰默认开启。

安装地址是整个仓库的 URL，不是 manifest.json、单个 JS 文件或 ZIP 的下载地址。酒馆服务端需要能够访问 GitHub，并已安装 Git。更新时使用酒馆的扩展管理功能检查更新。

也可手动安装：

1. 解压扩展 ZIP，得到 fate-dice-tray 文件夹。
2. 放入酒馆安装目录的 public/scripts/extensions/third-party/，确保 public/scripts/extensions/third-party/fate-dice-tray/manifest.json 存在，不要多套一层目录。也可放到 data/<用户目录>/extensions/fate-dice-tray/，仅供当前用户使用。
3. 保存工作，方便时刷新酒馆，在“扩展 → 管理扩展”确认“命运骰台 · 本地判定”已启用。
4. 从聊天输入区旁的扩展菜单打开“命运骰台”，或在扩展设置点“打开命运骰台”。

窗口支持拖动标题栏，拖动四条边缘或四个角调整大小；边缘取得键盘焦点后也可用方向键微调，Shift + 方向键调整 1 像素。窗口会限制在屏幕内，手机也可调整大小。

右上角“−”或 Esc 收起为可移动的小悬浮条，显示最新骰子点数；点“展开”或输入栏上方的按钮恢复。右上角“×”完全隐藏窗口，可通过输入栏上方按钮重新打开。收起或隐藏后，新结果继续计算和记录，不会强制展开窗口。最大化后点还原，再调整边缘大小。无背景遮罩，聊天页面仍可操作。窗口状态和位置在当前页面内保留，刷新后重新初始化。

酒馆“安装扩展”按钮不能直接上传本地 ZIP。卸载时先禁用扩展，关闭使用它的标签页，再删除文件夹。本地记录不会随文件夹删除。

## 自动掷骰

在酒馆发送输入 → 官方生成前拦截器读取本轮用户消息 → 本地规则分类 → 真实随机掷骰 → 窗口显示 → 结果自动附加到本次模型请求 → 模型生成正文。

不是在打字过程中反复掷骰。无需点击“掷骰”、手动复制结果或额外调用一次模型。默认开启，可在顶部“自动掷骰 → 设置与输入测试”调整：

| 输入 | 默认判定 |
| --- | --- |
| 攻击、躲避、跳跃、格挡、逃跑等行动词 | d20，修正 0，DC 12；合计 ≥ DC 成功 |
| 睡觉、睡到、休息、等待、第二天等词 | d100，20% 候选事件触发率 |
| 其余普通输入 | 默认做背景事件 d100；可取消“其余普通输入也进行背景事件检定” |
| 【不掷骰】、OOC / 场外指令开头、斜杠命令、已贴有骰台记录 | 跳过 |

关键词可自定义，逗号分隔。行动优先于时间跳跃；同一句包含两种条件时，首版只做一次行动检定。也可写【行动检定】或【事件检定】明确指定。对部分引号内对白与紧邻否定表达作排除，但这只是有限文本规则，不是完整语义识别。

例如：“织田跳跃躲开了斩击。”会自动做行动检定；“织田在床上睡觉，睡到了第二天早上六点。”会自动做候选事件检定。

DC、修正与概率须由你预先设定。首版不会从英灵面板、表格或上下文自动计算战力、难度或敌人位置。建议先在“设置与输入测试”中用上述例句试验。

## 同轮复用及请求注入

- 同一用户消息重生成、切换回复、群聊多角色生成时，复用第一次的点数和难度。
- 续写只复用已有结果，不新建检定。quiet、impersonate、未知生成类型不自动掷骰。
- 修改输入、换聊天、新增一轮输入建立新判定。修改规则不改写已判定轮次。
- 缓存按聊天身份、消息位置、发送时间和原文指纹区分。历史最多 100 次，会话缓存最多 200 轮；清空后刷新、超过保留范围或换设备会失去对应复用结果。
- 仅替换本次请求中的用户消息副本，在末尾加入“命运骰台自动裁定”区块；不修改保存的原始消息、预设、表格或时间字段，不调用酒馆设置保存接口。
- 随机源失败时阻止本次生成并提示，不编造点数。

模型仍负责解释后果，提示词不能保证所有模型严格服从结果。可在酒馆提示词查看功能中搜索“命运骰台自动裁定”，确认实际请求中存在判定记录。

已验证隔离环境中的拦截器、请求副本注入及面板通信，尚未执行真实模型生成测试或覆盖所有扩展组合。其他扩展若在之后删除或重写消息、截断上下文，或绕过标准生成流程，可能影响结果注入，需要实际联调。

## 界面试用及手动模式

双击“命运骰台_独立试用.html”，展开自动设置，在“试验一段用户输入”中输入文字并点击“测试自动判定”，即可观察分类及点数。独立 HTML 不连接酒馆，安装版才可拦截酒馆请求。

手动模式仍保留：

- 行动检定：普通 1d20，优势 2d20 取高，劣势取低，修正只加一次。自然 1 / 20 不自动必败 / 必成。
- 事件触发：d100 ≤ 触发率时触发。0% 必不触发，100% 必触发。
- 自由掷骰：D4 / D6 / D8 / D10 / D12 / D20 / D100，一次 1～20 枚。

手动结果支持复制、写入聊天草稿及导出。写入时保留原草稿，不点击发送；已贴骰台结果的输入跳过自动掷骰，避免重复。

历史存在浏览器 localStorage 的 fate-dice-tray.history.v1，规则存在 fate-dice-tray.auto.v1。同源下历史列表跨聊天共用显示，自动缓存另按聊天与轮次区分。记录时间是现实时间，不是剧情时间。浏览器拒绝存储时降级为临时内存记录，关闭页面前请导出。独立文件与安装版可能因来源隔离而分别保存。

## 公平边界

骰子不替代世界因果。模型应先判断能力、距离、反应速度与防护。高点数不能使不可能的动作变为可能，必然可行的普通动作也不应因低点数强行失败。失败可以是受阻、受伤或代价，不等于必死。

第三方介入须有动机、情报、位置及抵达条件。触发只说明候选事件检定通过，不指定一定出现枪兵或狂战士；没有合理候选时不得凭空刷敌。休息中断应发生在当前时间与目标时间之间，没有合理事件就正常休息，并保留原有日期关系。

使用 crypto.getRandomValues 和拒绝采样消除取模偏差，点数先产生一次，再播放动画。规则为简化系统，不是完整 D&D 或 Fate/TRPG。历史与指纹不提供防篡改、公证或防止反复试掷的保证。

## 官方依据与兼容性

查阅日期：2026-10-26。

- [官方 UI Extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/)：manifest、getContext、APP_READY、生命周期及 Prompt Interceptors。
- [官方扩展安装说明](https://docs.sillytavern.app/extensions/)。
- [官方 Extension-Dice 源码](https://github.com/SillyTavern/Extension-Dice/blob/main/index.js)：核对骰子菜单位置。
- 只读核对本机 /version 为 1.18.0 release；st-context.js 提供上下文；extensions.js 依序等待拦截器；script.js 在非 dry run 的提示词构建前调用拦截器。

使用 generate_interceptor 注册 globalThis.fateDiceTrayIntercept(chat, contextSize, abort, type)，同步完成随机判定及消息副本注入。未劫持发送按钮、修改酒馆核心文件或导入内部模块。最低版本限制为 1.18.0；其他版本尚未实测。

iframe 隔离面板样式，消息通道核对来源与窗口对象，用户内容用文本节点显示。菜单和手动草稿框没有稳定的专用官方 API，沿用当前官方骰子扩展菜单位置及 1.18.0 DOM 结构，检测缺失；未来核心 DOM 改动仍可能需要适配。
